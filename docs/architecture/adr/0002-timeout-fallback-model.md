# ADR-0002：模型超时兜底

- Status: accepted
- Date: 2026-11-07

## Context

无输入框助手默认使用 `workbuddy/deepseek-v4.1-flash`，单次请求最多等待 30 秒。
联网搜索和服务端排队偶尔会让请求超时；直接返回安全提示会中断一次完整的语音交互。
用户要求增加 `group/free`，只在其他模型超时时用于兜底，不改变正常回答的默认模型。

## Decision

- 默认模型保持 `workbuddy/deepseek-v4.1-flash`。
- 超时信号包括协程等待超时、`SocketTimeoutException`、异常类名或消息中的 timeout
  标记，以及 HTTP 408 和 504。
- 检测到超时后，助手主回答和媒体意图分类都改用 `group/free` 再请求一次。
- 助手主回答的兜底沿用生产 Responses API、搜索工具、输出上限和 30 秒单次等待窗口；
  媒体意图分类沿用其专用的无搜索请求和 15 秒单次等待窗口。
- 认证失败、其他非超时 HTTP/JSON/网络错误不触发 `group/free`；普通可重试错误仍只在
  已配置的主候选之间切换。

## Consequences

优点：

- 正常路径的模型、提示词和回答质量不变。
- 超时后可继续完成一次语音交互，而不是立即返回不可用提示。
- 兜底结果与主模型结果一样记录实际使用的模型名，便于日志区分。

成本与风险：

- 最坏情况下，一次助手主回答会在主模型 30 秒超时后再等待兜底模型 30 秒。
- `group/free` 对 Responses API、`web_search` 和当前提示词的兼容性尚未经过真机验收；
  现有模型延迟基准没有测试该模型。
- 免费模型的速率限制、排队和回答质量可能随时间变化，需要单独做设备验证。

## Alternatives considered

- 把 `group/free` 放进常规候选链：会在非超时错误时也切换，不符合“仅超时兜底”的要求。
- 超时直接返回安全提示：实现更简单，但会放弃一次可能成功的回答。
- 把 `group/free` 改成默认模型：会改变所有正常回答的质量和延迟，风险更高。
