# ADR-0003：定时足球直播

- Status: superseded in part by ADR-0004
- Date: 2026-11-07

> 2026-11-07 更新：主路径已改为由模型选择结构化动作；本文中的固定词解析仅保留为
> 模型不可用时的兼容兜底。当前实现见 ADR-0004。

## Context

用户会先问“英超今晚的比赛有哪些”，再要求“阿森纳比赛开始时帮我打开直播”。
第二句依赖上一轮回答中的球队和开赛时间；回答覆盖层消失、助手进程被回收或设备重启后，
只在内存里延时会丢失，不能保证自动打开直播。

## Decision

- 定时指令使用确定性解析，并在普通直播指令之前判断，避免“比赛开始时打开直播”
  被误判为立即播放。
- 首次赛程回答在内存中保留 12 小时，仅保存回答文本和时间戳；下一轮从回答中匹配
  球队、日期和时间。用户直接说出开赛时间时，不依赖上一轮上下文。
- 待执行日程写入应用私有 `SharedPreferences`，最多保留 16 条；同一球队和相近时间
  的一分钟窗口内去重。
- 使用 `AlarmManager` 的 `RTC_WAKEUP` 闹钟。允许多次定时，应用更新、设备重启或
  精确闹钟授权变化后恢复未过期日程。
- 有 `SCHEDULE_EXACT_ALARM` 特殊权限时使用 `setExactAndAllowWhileIdle`；没有权限时
  降级到 `setAndAllowWhileIdle`，并在语音确认中说明可能延迟。
- 闹钟使用 `PendingIntent.getActivity` 指向应用内不可导出的透明 Activity。系统启动
  该 Activity 后再复用既有 `LiveFootballLauncher` 打开球迹直播，避免广播接收器在
  后台直接启动外部 Activity 的不确定性。

## Consequences

优点：

- 不依赖前台服务常驻或当前界面存活，跨应用、跨进程可用。
- 到点启动由系统 `PendingIntent` 发起，比普通后台广播后自启 Activity 更稳妥。
- 精确权限缺失时仍有可解释的降级路径，不会静默失败。
- 只调用现有球迹直播 Intent，不复制播放器逻辑，也不保存媒体内容。

成本与风险：

- `SCHEDULE_EXACT_ALARM` 需要用户手动允许；部分电视系统可能没有直接入口，只能打开
  应用详情页。
- 近似闹钟受 Doze 和厂商后台策略影响，不能承诺准点。
- 透明 Activity 拉起外部应用仍依赖电视系统允许系统 PendingIntent 启动 Activity。
- 当前只解析文本赛程中的常见中文时间表达；回答被截断、时间缺失或同一时间匹配多场
  比赛时需要用户补充球队或时间。
- 当前没有语音取消或查看全部日程的入口。

## Alternatives considered

- 前台服务协程延时：界面离开或进程被回收后失效，不适合跨时段等待。
- `WorkManager`：适合后台任务，但不是精确时钟；可执行时间可能晚于开赛。
- 广播接收器直接启动球迹直播：实现更短，但受 Android 后台 Activity 启动限制影响。
- 云端定时推送：需要额外服务、账号、公网入口和凭据，超出当前本地助手边界。
