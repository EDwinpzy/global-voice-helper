# ADR-0004：模型选择定时动作与通用提醒

- Status: accepted
- Date: 2026-11-07
- Supersedes in part: ADR-0003

## Context

ADR-0003 用固定词组和中文时间解析识别“比赛开始时打开直播”。这条路径能工作，但用户
真正需要的是模型理解任意表达，例如：

- “阿森纳那场开球时直接切过去。”
- “等这部电影上线时提醒我，到时候问我要不要看。”
- “明晚节目开始后帮我打开。”

这些请求的共同点不是某个固定句式，而是模型需要理解上下文、未来时间、提醒方式和
下一步动作。继续增加关键词会不断出现漏判，也会把“到时执行”误判成“现在执行”。

## Decision

1. 助手主路径只发一次模型请求。模型正常回答时返回纯文本；需要设备动作时返回：

   ```json
   {
     "answer": "给用户显示和朗读的回答",
     "action": {
       "type": "SCHEDULE_REMINDER",
       "triggerAt": "2026-12-31T09:00:00+08:00",
       "title": "电影上线提醒",
       "message": "电影今天上线，要现在查找观看吗？",
       "confirmLabel": "现在查找",
       "followUp": {
         "type": "OPEN_VIDEO_SEARCH",
         "query": "电影名",
         "openFirstResult": false
       }
     }
   }
   ```

2. 请求中注入当前本地时间、RFC 3339 时间、时区和星期。模型负责把“今晚”“开赛时”
   “上线日”等表达换算成绝对时间；客户端再次校验时间必须是未来，不直接信任模型。
3. 可执行动作采用封闭白名单：立即打开足球直播、立即搜索影视、立即播放音乐、定时
   打开足球直播、定时提醒。定时提醒可选择到点询问，也可自动执行一个后续白名单动作。
   模型决定使用哪一个，但不能构造任意 Intent、URL 或代码。
4. `SCHEDULE_REMINDER` 是通用能力，不绑定电影或足球。到点时由透明 Activity 显示提醒
   并交给原厂 TTS 朗读；如果带有 `followUp`，同时显示“现在查看/稍后”选择。用户确认
   后才调用对应 App 的既有语音 Intent。只有用户明确要求“到点直接执行、不要询问”时，
   模型才设置 `autoRunFollowUp=true`；此时 `followUp` 必填，到点直接执行该白名单动作。
5. 模型只能为能够确定的具体未来时刻安排提醒。电影上线等易变化信息必须先搜索核实；
   没有可靠时间时用普通文本询问，不能编造日期。只有日期、没有时刻且用户要求当天
   提醒时，按本地当天 09:00 处理，并在回答里说明。
6. 最近两轮对话在内存中保留 12 小时，避免回答浮层消失后无法理解“它”“那场”等指代。
   正常情况下新听写会保留上下文；失败、用户主动取消或外部 App 启动完成后清空。
7. 通用提醒和足球日程分别持久化到应用私有 `SharedPreferences`，最多各 16 条。相同
   标题和一分钟内的时间视为重复。开机、覆盖安装和精确闹钟授权变化后恢复未过期日程。
8. 固定词解析器保留为模型配置或网络完全不可用时的兼容兜底，不再是正常主路径。

## Consequences

优点：

- 用户不需要记住固定命令，可由模型组合上下文、搜索和结构化动作处理新表达。
- 通用提醒可以覆盖“上线、开播、发布、到某天处理”等一次性场景，而不是每类内容
  都新增代码分支。
- 明确要求自动执行时，同一套任务存储和闹钟可以覆盖到点播放音乐、打开直播或进入
  影视搜索，不需要为每种媒体复制一套定时实现。
- 动作白名单和本地时间校验限制了模型误判的影响范围。
- 到点提醒有界面、TTS 和可选确认动作，不需要助手界面一直存活。

成本与风险：

- 设备操作类请求也需要等待一次模型响应；网络不佳时比固定词路径慢。
- 模型仍可能选错动作或生成错误时间。当前只能校验格式、必填字段、过去时间和应用
  可用性，不能证明用户真实想要的语义一定正确。
- 当前只支持一次性定时，不支持持续监控“降价、有货、上线状态变化”等没有明确时刻
  的条件。遇到这类请求，模型应要求用户给出可执行时间，不能假装已经监控。
- 到点页面依赖系统允许闹钟启动 Activity；没有精确定时权限时会降级为近似调度。
- 上线时间、平台库存和可播放性由外部信息决定，定时提醒不等于保证内容已经可用。

## Alternatives considered

- 继续扩展关键词和时间正则：可预测但无法覆盖“不确定场景”，并且容易误触发。
- 先正常回答，再发第二次模型请求判断动作：延迟更高，且第二次仍可能缺少上下文。
- 让模型直接生成 Intent 或脚本：能力最大，但不可审计，也无法接受安全边界。
- 只发系统通知：电视上容易被忽略，也不能完成“现在看/稍后”的交互。
- 使用周期轮询监控价格或库存：需要明确的轮询频率、后台限制、成本和误报策略，
  当前没有可靠产品契约，因此不纳入本次范围。
