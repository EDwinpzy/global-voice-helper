## 路由结论

- 歌曲、歌手、音乐入口 → Folia。
- 电影、电视剧、动漫、综艺、短剧、纪录片 → Video Pro。
- 足球直播、球队比赛、赛事直播 → 球迹直播。
- 用户明确说抖音/短视频 → 抖音 TV。
- 影视仓仅按应用名打开；没有安全契约时不推测内部页面，也不发通用广播冒充播放成功。

## 模型优先路由实机验收

最终替换安装的是 helper `1.6 (7)`（OptimalTV 证书）和 Folia
`0.7.27-android.450 (488)`（Folia release 证书）。以下用媒体会话、Activity 路由日志
和实际 `PlaybackState` 判定，不以“目标 Activity 已到前台”代替播放成功。

| 输入 | 目标与结果 |
|---|---|
| `播放晴天` | `VOICE_PLAY` → Folia；元数据 `晴天 / 周杰伦`，最终 `state=3` |
| `播放每日推荐` | `music.daily_recommendations`；队列 30，最终 `state=3` |
| `打开私人FM` | `music.personal_fm`；队列 5，最终 `state=3` |
| `播放我喜欢` | `music.liked`；队列 41，最终 `state=3` |
| `播放歌单车载MP3永久保留曲目` | `music.playlist`；队列 48，最终 `state=3` |
| `播放电台VIP专属推荐` | `music.radio`；队列 30，最终 `state=3` |
| `播放流浪地球` | Video Pro 搜索桥；日志出现 `route → detail/{vodId}` |
| `播放无双` | `action=none`，追问电影还是歌曲，没有启动播放器 |
| `播放音乐云盘` | `music.cloud` 选中云盘条目，但播放停在 `state=2`；手动“音乐云盘 → 播放全部”同样失败，不是语音路由回归 |

已知未通过或未覆盖的路径：

- 抖音搜索层能收到 `在抖音看三国演义`，但平台显示安全校验/不可用，未证明实际播放。
- `播放拜仁` 在最近一次实机查询中没有正在进行的比赛，模型返回普通文本；没有完成
  有赛程时的球队选择验收。
- 本表来自调试文本入口和注入的识别链路，不是物理遥控器麦克风验收；真实音频输出
  仍需人工听音确认。

## 入口匹配边界

- Folia 的“我喜欢/私人FM/每日推荐”使用固定语义 ID。
- 音乐云盘、歌单、收藏专辑、推荐电台按当前首页卡片的显示名称匹配；未登录、provider
  未返回该卡片或名称被修改时，不能保证播放。
- 名称先精确匹配，再接受唯一前缀或唯一片段；同时匹配多张卡片时不执行，避免误播。
- 推荐电台卡片如果带自己的 station，就按该 station 开播；普通推荐歌单按集合读取。
- WebView 冷启动时账户、曲库或电台数据可能尚未加载，Folia 会在最多 20 秒内等待并重试
  语义入口。
- 球迹只支持足球；NBA、网球、F1 等不能路由到球迹。
- “启动 Activity 成功”不等于“内容已播放”；登录、搜索校验、空结果和平台限制由目标
  App 自己显示。
